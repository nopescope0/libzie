## Overview

"libzie" (formerly "Ders Arşivi") — a local-only web app for organizing course materials (PDFs, slides). Code, comments and documents are in English (the GitHub README is Turkish); the UI is available in Turkish and English (see "Languages" below). Every user-facing string goes through an ID in `static/lang/<lang>.json` — never hard-code UI text in `index.html`/`server.py`.

No dependencies, no build step, no tests, no linter: Python standard library on the backend, a single vanilla HTML/CSS/JS file on the frontend. Two helper checks exist: `python tools/i18n_check.py` (language ids) and `python tools/theme_check.py` (theme contrast). Privacy facts (what leaves the machine) are in `PRIVACY.md`; keep it and the About-tab text (`about.privacy`) in sync if a new network call is ever added.

## Running

```bash
python server.py               # serves http://127.0.0.1:8765 and opens the browser
python server.py --no-browser  # same, without opening a browser (used by .claude/launch.json)
```

End users get the packaged Windows app (installer / portable exe, see "Desktop app" below); `baslat.bat` is only a local, untracked (gitignored) demo launcher kept by the maintainer. The `PORT` env var overrides the port (useful when 8765 is already taken by the user's own running instance — don't kill it; test on another port with a scratch copy of the project so the user's real files aren't touched).

The content folder defaults to `./materials`. It can be changed from the in-app Settings dialog (writes the gitignored `settings.json`, applied immediately without a restart; see `settings.example.json`) or pinned with the `LIBZIE_MATERIALS_DIR` env var (which locks the dialog) — intended for a Google Drive folder that Notability auto-backs-up PDFs into. If the configured folder doesn't exist at startup (e.g. Drive not mounted) the server falls back to `./materials` and `/api/tree` returns a `warning` that the UI shows as a banner; it never creates the configured path.

**Names on disk (English since 2026-10).** Older versions used Turkish names: `kaynaklar/` → `materials/`, `ayarlar.json` → `settings.json`, `oturum.key` → `session.key`, `.silinenler` → `.trash`, `.renkler.json` → `.colors.json`, `.ikonlar.json` → `.icons.json`, env vars `KAYNAK_KLASORU`/`LIBZIE_OTURUM_DOSYASI`/`LIBZIE_GUNCELLEME_URL` → `LIBZIE_MATERIALS_DIR`/`LIBZIE_SESSION_FILE`/`LIBZIE_UPDATE_URL`, and settings keys (`kaynak_klasoru`, `arka_planda`, `otomatik_guncelleme`, `son_otomatik_deneme`, `dil`, `tray_ipucu`) → `materials_dir`, `run_in_background`, `auto_update`, `last_auto_attempt`, `lang`, `tray_hint_shown`. `server.legacy(new, old)` migrates them: the packaged app renames the old file/folder once; from source the old name is simply kept in use (a developer's other instance may be running). `read_settings()` maps old keys to new ones (`LEGACY_KEYS`). Release assets are only `libzie-setup.exe` / `libzie-portable.exe` (+ `SHA256SUMS.txt`). Installed versions ≤ 0.1.6 look for the old Turkish asset names, so their in-app update stops working from v0.1.7 on; those users must download the new version once by hand.

## Architecture

- **`server.py`** — `ThreadingHTTPServer` bound to `127.0.0.1` only. The filesystem is the database: the content root (`ROOT`, default `materials/`, gitignored) holds the user's files, and its folder hierarchy *is* the course/folder structure. There is no metadata store, so files added via Explorer show up automatically.
  - `GET /api/tree` returns the whole nested tree (`{name, path, folders[], files[]}`); hidden entries (dot-prefixed) are skipped.
  - `GET /files/<path>` serves files inline, with single-range `Range` support (206/416) so pdf.js and the browser's PDF viewer can read big files in chunks; a `?v=<mtime>` query is ignored server-side and only busts client caches. `GET /vendor/<name>` serves vendored third-party files from `static/vendor/` (pdf.js 3.11.174 `pdf.min.js`/`pdf.worker.min.js` from cdnjs, Apache-2.0; the Linux Libertine OTFs) — flat filenames only.
  - `POST /api/upload?dir=&name=` takes the **raw file bytes as the request body** (not multipart; the `cgi` module is gone in Python 3.13+). Name collisions get ` (2)`, ` (3)`… suffixes via `unique()`.
  - `POST /api/mkdir|move|delete|open|reveal` take JSON bodies. `move` handles both rename and relocate (`{from, dir, name?}`). `delete` is a soft delete into `materials/.trash/` and returns the `trash` name; `POST /api/restore {trash, to}` moves it back (appends " (2)" on a name clash, `clean_name`/`safe` guarded) and powers the "Undo" toast. `GET /api/preview?path=` reports `{exists, courses, files, capped}` for the Settings folder preview (read-only, skips dot entries, caps at 20k files). `open`/`reveal` launch the OS default app / file explorer (needed because browsers can't render .pptx/.docx).
  - Every client-supplied path must go through `safe()` (resolves and rejects anything outside `ROOT`) and every new name through `clean_name()`. Errors are returned as `{"error": "..."}` with status 400 and shown as toasts by the frontend.
- **Security (2026-10 hardening round):** on every request `server.py` applies in order `guard()` (Host ∈ 127.0.0.1/localhost/[::1]:port → DNS rebinding; `Sec-Fetch-Site` same-origin/none; on POST an `Origin` match + the custom `X-Libzie: 1` header → CSRF) and `authorized()` (session-key cookie `libzie_k`); only `/api/ping` needs no key. The key lives in `%APPDATA%\libzie\session.key` and is **renewed at every server start** (`start()` → `new_token()`; `LIBZIE_SESSION_FILE` is for tests only); on the first open `/?k=<key>` is turned into the session cookie (`libzie_k_<port>`, HttpOnly, SameSite=Strict, no `Max-Age`) (`launch_url()`; `app.py` and `server.main` use it). Before connecting to a running instance `is_libzie()` calls `/api/ping?n=` with a random number and if the `proof` in the reply (= HMAC-SHA256(key, n)) does not verify, it does not trust the other side and does not send the key (port squatting). The server uses `SO_EXCLUSIVEADDRUSE` through the `Server` class (on Windows it stops another process from co-binding the same port and stealing connections). Write operations are guarded by `check_write()` (system/Startup/`%APPDATA%\libzie`/`%LOCALAPPDATA%\Programs` folders cannot be written to) and, on upload/rename, `check_ext()` (`BLOCKED_EXT`: exe, bat, ps1, lnk… cannot be added); `svg` is not in `OPEN_OK`. **While developing**, opening `preview_start`/the browser at `http://127.0.0.1:8765/` gives 401: open it with `?k=<value in the key file>` (the cookie stays). Every client `fetch` POST must send `X-Libzie: 1` (`api()` and the upload already do; don't forget it when adding a new POST). `/files/` serves everything except PDF with `Content-Security-Policy: sandbox` (an SVG/HTML that lands in the user's folder cannot run scripts); the app page uses `CSP_APP` (no eval, `connect-src` only self + Open-Meteo); pdf.js `isEvalSupported: false` (CVE-2024-4367). `/api/open` opens only extensions on the `OPEN_OK` allow list (executable types are redirected to "Show in folder"); `clean_name()` rejects Windows reserved names and a trailing dot; the JSON body is capped at 1 MB; the course color is validated on the server as `#hex` and the client filters it again with `colorOf()`. Don't skip this chain when adding an endpoint; if a new external domain is needed add it to `CSP_APP`. Workflow (`windows.yml`): the build job only reads, publish permission is only in the `publish` job; actions are pinned to a commit SHA (Dependabot updates them); the tag name is passed through `env`; every release gets a `SHA256SUMS.txt`. See `SECURITY.md`.
- **`updater.py`** — in-app update (Settings → About). `VERSION` is kept here; at build time GitHub Actions rewrites this line from the tag (`v0.1.3` → `0.1.3`), so there is no need to bump it by hand. `check()` reads GitHub `releases/latest` (no release / private repo → 404 → "No published release found"). `kind()`: if packaged and `unins000.exe` sits next to the exe it is `installer`, otherwise `portable`, if not packaged `source` (no update is applied). `start_apply()` downloads the asset (`libzie-setup.exe` / `libzie-portable.exe`) to temp in a background thread (size + MZ + **mandatory** sha256 verification: GitHub's asset `digest` field, else `SHA256SUMS.txt` in the release, and if neither exists the update is refused; the address comes only from this repo's `releases/download/` path, no URL is ever taken from the client), then for `installer` starts the wizard with `/SILENT /CLOSEAPPLICATIONS`, for `portable` starts a hidden-console `swap.bat` (it tries `move /y` until the exe is unlocked, then starts the new exe) and calls `os._exit` after 1.5 s. PyInstaller's `_PYI*`/`_MEIPASS2` environment variables are not passed to launched processes (otherwise the new single-file exe looks for the deleted temp folder). While the wizard is silent `libzie.iss` reopens the app (`Check: WizardSilent`). The `LIBZIE_UPDATE_URL` env var points the release address at a fake server (for trying only). Endpoints: `GET /api/update/check|status`, `POST /api/update/apply|settings`; `settings.json` keys `auto_update` and `last_auto_attempt` (the automatic update on startup tries each version only once so a failure does not loop). UI: the "update" block in `static/index.html` (`initUpdate`, `checkUpdate`, `pollUpdate`, `autoUpdate`; runs 4 s after startup).
- **`static/index.html`** — the entire frontend. State is the fetched `tree`, the current folder `cur` (kept in the URL hash, `#/<encoded path>`), and the search `query`; `render()` redraws the sidebar tree, breadcrumbs and content from that state. The tree is re-fetched after every mutation and on window focus. Paths are always `/`-separated and relative to `materials/`.
  - Search uses `norm()` to fold Turkish characters/diacritics so "isletim" matches "İşletim". The search box (`#q`) lives in the top bar; the `/` / Ctrl+K shortcut first leaves the file view because the top bar is hidden there. The sidebar slot under the brand is a plain HH:MM clock (`#clock`, `renderClock()` every second, blinking separator, full date in its tooltip); it deliberately uses a 4px radius instead of `var(--r)`. The brand has an inline SVG logo (`.brand-logo`): three leaning books on a shelf spelling "lib" (the "i" book's dot `.logo-dot` is a stroke-less accent-filled circle). The side books' ±8° lean lives in CSS (`.logo-l`/`.logo-b`, `transform-origin` at their bottom corners in SVG units), not in SVG `transform` attributes, so the hover `topple-l`/`topple-b` animation (stand upright → topple back with slight overshoot, "b" delayed) can override it. Coordinates were chosen so the 1.3-stroke books touch without overlapping at rest. Next to the clock, `#weather` shows an outline condition icon (`weatherIcon()` → `W_ICONS`, grouped by WMO code; parts carry `wi-*` classes for slow looping CSS animations — rays spin, clouds drift, drops/flakes fall with staggered `--d` delays, bolt flickers; falling parts start at opacity 0, so the reduced-motion rule forces them visible) + current temperature + today's expected condition from Open-Meteo (no API key; WMO codes mapped in the language files as `wmo.<code>`). The city is chosen from a select box of Türkiye's 81 provinces (İzmir, Ankara and İstanbul on top; "Other city…" falls back to a typed geocoding search; saved as `weatherPlace`); browser geolocation is intentionally not used. Results are cached 15 min in `localStorage` (`weather`); one request fetches `current` (temp, feels-like, code, is_day), `hourly` (code, precipitation probability) and `daily` (min/max): the icon uses the current code (a moon at night), the text is the day's expectation from `dayCode()` over the remaining hours (severe codes ≥51 only count if they last ≥2 h, because the daily WMO code is the day's worst), the right-hand column shows max/min (`#w-range`), the tooltip adds feels-like and rain chance and the last value is shown offline — this is the app's only outbound network call besides the update check, so keep it optional.
  - The home greeting is split into per-letter spans for its hover animation (staggered `letter-wave`); "i"/"İ" are rendered as dotless "ı"/"I" plus an absolutely positioned "˙" (`.tittle`) so the dot can hop on its own. The tittle offsets (`.02em`, `-.13em`) were measured for Linux Libertine — re-measure if the font changes. The plain text is kept in `aria-label`. The same animation auto-plays once per page load (`.hi.play`, guarded by `greetPlayed`, delayed .35s to follow the content entrance, class removed afterwards so hover still works); the window-focus reload is skipped for the first 3s after boot (`bootAt`) so it can't re-render the greeting mid-animation.
  - Drag-and-drop distinguishes internal moves (custom `application/x-libzie-path` data type) from OS file drops (`Files`). Dropped folders are walked via `webkitGetAsEntry`, preserving their structure.
  - Extensions in `VIEWABLE` open in the in-page iframe viewer; anything else is sent to `/api/open`.
  - Folder/file context menus are shared between the `⋯` buttons and right-click: `menu(anchor, items, pos)` / `folderMenu()` / `onRightClick()`; pass `pos` for cursor placement. `ask()` resolves from its own button handlers rather than the `<dialog>` `close` event (that event doesn't fire reliably in the embedded Browser pane, so don't build flows on it); its result is returned through `setTimeout` (otherwise the `close` event of one dialog closed a second one opened right after it).
  - Opened files live in tabs above the content area (`tabs`, `active`; `active === null` means the file browser). One `<iframe>` per tab is created lazily and hidden/shown, never recreated, so PDF scroll position survives tab switches. `syncTabs()` runs after every `load()` to prune tabs for deleted files and bump the iframe's `?v=<mtime>` when the file changed on disk (Notability re-backups); `afterMove()` remaps tab paths. Any folder navigation or search resets `active` to `null`.
  - Viewer space is deliberately maximized: while a file is open (`main.viewing`) the top bar is hidden and the tab bar (`#tabbar`: tabs + "open in default program" + sidebar toggle) is the only chrome; iframes load with `#view=FitH&navpanes=0`. The sidebar collapses via `body.side-collapsed` (`--side-w` var, Ctrl+B, persisted as `sidebar`).
  - Meaningful motion (state/continuity/feedback) lives in the "motion: continuity and feedback" block: `transition(update, nameOld, nameNew)` wraps View Transitions — home tile ⇄ course page (`go()` uses `history.pushState` + synchronous `render()` inside the transition; tile shape `vt-shape` flies to the breadcrumb course icon, tile `vt-tile` zooms/blurs out) and thumbnail/row → viewer (`vt-doc`). It always falls back to a plain update when unsupported, under reduced motion, or if the update callback hasn't run within 400ms (frozen/background windows), and swallows aborted-transition promise rejections. Feedback: `arrivals` (paths added by upload/rename/move get `.arrive` on their next render, cleared in `load()`), `flashAccept(dir)` on a successful drop, `leave(path)` fades items before delete (capped at 260ms, returns an undo for failures), and `toast(msg, err, stay, progress)` draws a progress bar. Cards, rows, tiles and tree nodes carry `data-path` for this.
  - Motion values use the transitions.dev token scale declared in `:root` (`--duration-*`, `--ease-*`, `--distance-*`, `--scale-*`, `--blur-*`; `--ease` is kept as an alias of `--ease-smooth-out`). Pick tokens by what the motion does, not the nearest number: opens slower than closes (sidebar 400/350, toast 250/350, menus/dialogs open 250), hover-ins ≤250ms with no delay on hover-out, stagger 40ms with ≤300ms total, emphasis moments 500ms. Deliberately off-scale: continuous loops (weather icons, clock, upload arrow), the logo topple and greeting tittle hop, the 600ms thumbnail zoom (user-requested), and the greeting wave's 12×40ms total. JS-driven `leave()` uses literal token values (150ms, smooth-out).
  - Animations are CSS-driven and gated: `render()` adds `#content.enter` only when `animateNav` was set (folder navigation via `go()`/`hashchange`, or returning from a file view), never on focus-triggered reloads or uploads. `renderTabs()` rebuilds the tab bar only when the tab list/colors change so the active-underline transition runs in place; PDF iframes crossfade through the `.on` class (not `hidden`). Everything collapses under `prefers-reduced-motion`.
  - UI palette is navy + orange by default (dark theme). **Colors are not in `index.html` anymore:** they live in `static/themes/<id>.json` (see "Themes" below) and reach the CSS as `:root` variables (`--bg`, `--side`, `--surface`, `--hover`, `--line`, `--line-strong`, `--shelf`, `--text`, `--muted`, `--faint`, `--accent`, `--highlight`, `--highlight-hover`, `--on-accent`, `--danger`, `--warn`, `--shadow`, `--scrim`, `--t-pdf/slide/doc/sheet/img`). Use the vars, never literal colors, and use `color-mix(in srgb, var(--accent) N%, transparent)` for translucent tints. Theme-independent constants only: the thumbnail glass buttons (`--glass*`, defined in `:root` of `index.html`), the `rgba(0,0,0,.18)` hover overlay on course-colored tiles, and the course `PALETTE`/ink colors in JS.
  - Design language (modelled on jackywinter.com's landing grid): flat solid-color blocks, sharp corners, 5px dark gaps, thin outline shapes, large regular-weight serif type. Keep to it: every `border-radius` uses `var(--r)` (2px), grid gaps use `var(--gap)`, two font roles, both from the Linux Libertine 5.3.0 release (GPL+font exception / SIL OFL, OTFs in `static/vendor/` + `LinLibertine-OFL-1.1.txt`, downloaded from the official SourceForge release; `@font-face` prefers a Windows-installed copy via `local()`): `var(--font-head)` = Linux Libertine (serif) only for headings — `h2`, `.brand`, the greeting, the clock and the weather temperature (one selector list next to the `button, input` reset); `var(--font)` = Linux Biolinum (its sans companion) for everything else, including course names, because the serif looked harsh at small sizes. Section headings are large sentence-case, not small uppercase labels.
  - Courses render as solid-color tiles (`courseTile(f, index)`): on the home page as large tiles plus a trailing "New course" tile, inside a course as `.tiles.small` for subfolders. Tile background is the course color darkened 15% and text color is picked by WCAG contrast (`tileColors()`, see the accessibility pass below); the same pair (`tileVars()` → `--tile`/`--ink`) fills the active tab and the active sidebar node. Sidebar course rows have no hover background: a `::before` in the course color is clipped by a 5-point `clip-path` polygon that morphs hidden → small left triangle (hover) → full row (active). Because `renderTree()` rebuilds the list every render, rows are built with the previous selection (`treeActive`) and then flipped to `cur` after a forced reflow, so the fill/drain transition actually plays. Shapes come from the course icon (see "Course icons") by alphabetical index so siblings get distinct shapes; hover swaps the shape for file count/last-modified + arrow.
  - Folder file listings default to a thumbnail grid (`fileView`, toggle persisted as `view`; search results and "Recently opened" stay list rows). PDF first pages are rendered lazily with pdf.js (`IntersectionObserver`, max 2 concurrent, `buildThumb`) and cached as JPEG blobs in IndexedDB (`libzie-thumbs`) keyed by `path|mtime|size`; images use themselves; other types show an extension badge. `fileMenu()` is shared by rows and cards.
  - Accessibility/usability pass (from the critique): text on a course color is chosen by WCAG contrast in `tileColors()` (tries `INK_DARK`/`INK_LIGHT`, nudges the tile bg the least needed to reach 4.5:1) — never reintroduce a luminance cutoff. Every `.tile/.tcard/.row/#tree .node/.tab` is a focus stop (`tabindex=0`, roles, `aria-*`); one delegated keydown handler gives Enter/Space = click, arrows via `neighbor()` (geometry-based), F2 = rename, Delete = remove, and only fires when the element itself (not its inner ⋯/× button) is focused. `:focus-visible` ring + `:focus-within .more` keep the hover-only ⋯ reachable. `toast(msg, err, stay, progress, action)` takes `{label, fn}` for "Undo" (delete → `/api/restore`, move → move back). Inside a course the course chip is hidden (`courseBadge()`), the files heading is "<course> files", search is scoped to the current course (`searchAll` toggle) and the breadcrumb keeps the path; subfolders inside a course use the compact `.tiles.small`; the home page shows courses as books on a shelf (see The Shelf below). Weather icon loops run only on hover/focus, the clock separator is static, and `.paused` (set on `visibilitychange`) freezes every animation while the tab is hidden.
  - `localStorage` (wrapped in try/catch via `store`) only holds per-browser conveniences: recently opened files, expanded sidebar nodes, and the open tabs (plus language, theme, view, sidebar, weather).
  - Critique pass (2026-10): home order is greeting (38px) → "Continue" (4 most recent files, from `recent`) → "Courses". Ctrl+K sets `searchAll` (global quick-open) and Enter in `#q` opens the first `searchResults()` hit (contiguous phrase matches rank first); `/` stays scoped to the current course. `?` opens the `#keys` shortcut dialog (also a "Shortcuts" sidebar button). The sidebar auto-collapses below 900px unless the user saved a Ctrl+B choice (`narrowMQ`; the auto state is not persisted). Course-page file cards get a 3px course-color spine (`.tcard::after`) and a `.ftag` chip parsed from the name (`fileTag()`: "Lecture 3", "Chapter 1", "Midterm"); files sort naturally (`byName`, numeric collation). Thumbnail queue renders the topmost visible card first, 3 at a time. Keys typed while the PDF iframe has focus go to the browser's PDF viewer and cannot be intercepted, so Esc, `/` and Ctrl+K only work after clicking outside it (the shortcut dialog says so). Not done: remembering the page inside a PDF (the embedded viewer exposes no page).
  - The Shelf (2026-10, from the Figma design in "libzie Design System"): the home page is greeting (72px) → "Continue" (3 `resumeCard`s: folder-tab cards with the file tag) → "Courses" as `.shelf` of `bookTile()`s (spine = vivid course color with a vertical `writing-mode` title, cover = `tileColors()` bg, height `150 + 6 × files` clamped 190-300, hover lifts 8px) plus `newBook()`. A course page starts with `courseHeader()` (22px color spine + 64px serif title + counts); file cards (`fileCard`) are a `.ptab` trapezoid tab (from `fileTag()`, empty spacer when no tag) above a `.tbody` (thumb + info). `.rtab`/`.ptab` share the trapezoid clip. `.book` and `.rcard` are in `NAV_ITEMS`; `nameCourseTile()` also finds `.shelf .book` for the view transition. Hard-coded rgba overlays and the scrollbar SVG strokes were re-colored to the new palette alongside the vars.
  - Engineering ornament (2026-10): `gearsSvg()` (meshing 12/8-tooth pair, `.gears`) sits in `.greet` and `.chead` and is spun by `spinGears()` (rAF physics, not CSS): hovering the gears themselves (`.gears .g-a/.g-b` have `pointer-events: all`; the SVG is otherwise inert) accelerates gear A to 140°/s in 1.5s (B = -1.5x A to stay meshed) and leaving coasts to a stop in 2.3s; the rAF loop ends when the speed reaches 0, bails out if the SVG was re-rendered, and does nothing under reduced motion. The timings match the Figma motion frame "Motion — Shelf and Gears"; `#circuit` is a static inline SVG PCB in `<main>` behind `#content` (z-index 0 vs 1), hidden under `.viewing` and below 900px; `.sec-rule::after` is the solder-pad ring.

Pads at the four ends and every other crossing; redrawn by a `ResizeObserver` on `aside`. Static, 50% opacity, `pointer-events: none`.

The flames are off at rest: hovering the shuttle's hull paths (`.schem > path:not(.spark)` has `pointer-events: all`) fires them through `fireRocket()` (`--thrust` 0..1, `.fire`: three layers per engine plus sparks; full thrust in 0.5s, dying out in 1.1s), independent of the gears.

## Themes (2026-10)

- **Files:** `static/themes/<id>.json` = `{ "scheme": "dark" | "light", "vars": { "--bg": "#0e1a2b", ... } }`. The default theme `navy` (dark-scheme navy-orange; `themes.DEFAULT`) must always exist; missing variables in the other themes come from it. Display names are in the language files as `theme.<id>` (and `theme.auto`).
- **Server (`themes.py`):** validates the files and turns them into CSS. Only `ALLOWED` variable names and only color values (`#hex`, `rgb()`, `hsl()`) are accepted; an invalid theme is skipped (warning on stderr). So a theme file cannot slip other CSS, an external resource or `</style>` into the page. `Handler.send_index()` embeds the CSS in `<style id="themes">` (`/*THEMES*/`) and the `[{id, scheme}]` list in `<script id="themes-data">` (`/*THEMES_JSON*/`). The default theme is also applied to `:root`, and every theme to the `.theme-prev[data-theme]` preview cards; the scrollbar arrows (a data URL cannot take a CSS variable) are generated from each theme's `--accent`.
- **Client:** `<html data-theme="...">` selects the active theme; a small script in `<head>` applies it before the first paint (no flash), and the "theme" block in the main script (`applyTheme`, `setTheme`, `buildThemePane`) manages the choice. The choice is `localStorage` `theme` = `auto` (default; follows the system `prefers-color-scheme` live) | a theme id; an unknown value falls back to `auto`. `<meta name="theme-color">` is updated with the active `--bg`. Settings → Theme: cards with previews (`role="radio"`, navigated with ←/→).
- **Adding a theme:** create `static/themes/<id>.json` (id `[a-z][a-z0-9_-]{1,23}`), add the `theme.<id>` name to `en.json`/`tr.json`, run `python tools/theme_check.py` (WCAG contrasts: text ≥7, muted/small text and buttons ≥4.5) and `python tools/i18n_check.py`, and check it by eye (home page, course page, settings, menus). If a new color variable is needed, update `themes.ALLOWED`, `navy.json` (and `CHECKS` in `theme_check.py`).
- On the roadmap: user-defined themes (`%APPDATA%\libzie\themes`).

## System tray (2026-10)

- **`tray.py`:** the `Tray` class, a `Shell_NotifyIconW` icon through ctypes with no extra dependency (a hidden top-level window + message loop in its own thread). Left/double click → `on_show`, right click → menu (Open, Check for updates [if `on_update` is given], Quit; the language is read from `lang()` every time it opens; in `app.py` the update item shows the window and runs `openSettings('about')`, and the About tab starts the check), `WM_CLOSE`/`WM_ENDSESSION` → `on_quit` (setup wizard / session end), `TaskbarCreated` → the icon is put back (if Explorer restarts). `remove()` deletes the icon synchronously (so no ghost icon remains before `os._exit`), `stop()` closes the thread, `balloon()` gives a short notification. Icon: in the packaged app the exe's own icon (`ExtractIconW`), from source `assets/icon.ico`. Outside Windows `start()` returns False.
- **`app.py`:** if the tray was set up successfully, the `window.events.closing` handler, while the "Keep running in the background when the window is closed" option is on (`server.tray_enabled()`, `settings.json` `run_in_background`, on by default), **hides** the window and cancels the close (pywebview: the close is cancelled if the handler returns `False`); a real exit is from the tray menu through `quit_app()`. A balloon hint is shown once on the first hide (`tray_hint_shown`). Second launch: if `server.start()` connects to a running instance, `server.request_show(url)` brings it to the front (`POST /api/desktop/show`, `DESKTOP_HOOKS["show"]`) and exits; if the running instance is not a desktop one (`DESKTOP` is False) a new window opens as before. Before the update does `os._exit`, `updater.EXIT_HOOKS` (removing the tray icon) run.
- **Settings:** `POST /api/settings/general { tray?, lang? }` (`GET /api/settings` → `desktop`, `tray`). The language is also kept on the server (`lang`) so the tray menu uses the same one; if it is `auto`, `tray.system_lang()` (the Windows UI language). The checkbox in the General tab is disabled outside the desktop app.
- **Testing:** since pywebview could not be followed, the flow was tested with a fake `webview` module (closing/hide/show/destroy) and at the tray API level (`Shell_NotifyIconGetRect`, `PostMessageW`); the first trial in a real window is made with the exe built in CI.

## Settings window (2026-10)

- `<dialog id="settings">` is large and tabbed (880x640): a vertical `role="tablist"` on the left (`.set-nav`: General, Theme, Content folder, About), the selected tab's `role="tabpanel"` (`.set-pane[data-pane]`) on the right. In a narrow window (<700px) the tabs turn into a horizontal strip on top. Tab title ids are `set.tab.*`.
- `selectSettingsTab(name, focus)` opens a tab (roving tabindex, `aria-selected`; ↑/↓, ←/→, Home/End navigate); `openSettings(tab)` opens with a given tab (the "Settings" button in the content-folder warning opens `'folder'`), and if no tab is given the last tab of the session (`lastSettingsTab`). The window is closed by the top-right `#s-cancel` (×) and Esc; "Save" is only for the path in the Content folder tab (language and auto-update are saved instantly).
- **Open/close animation (2026-10, rewritten):** a shared-element transition. The gear in the sidebar (`#open-settings svg`, name `vt-gear`) flies to the same gear in the window title (`#set-gear`) (open `--duration-slow` 400ms, close `--duration-fast` 250ms, `--ease-smooth-out`, 180° = 3 teeth of rotation); the window itself comes with the `pop` opening of `dialog[open]` like the other windows (250ms, 0.96) and **is left alone**; the root cross-fade is off on opening (`vt-set-open`), 150ms on closing (`vt-set-close`). `transition(update, nameOld, nameNew, after)` + `showSettingsDialog()`/`closeSettingsDialog()`; Esc (`cancel`), × and a click outside the window (the press must also start outside) close with the animation, save closes instantly. Blur, a circle mask, a big gear and a rotation speed-up are **not used** (they turned the thin line into a halo that looked like a "ring"; reasons in docs/UI-GUIDE.md §4). `openSettings()` starts the animation without waiting for data. If unsupported / motion reduced / no frame within 400 ms it opens plainly.
- The version check (goes online) runs only when the "About" tab is first opened (`initUpdate`, `aboutLoaded`). The "Theme" tab holds the theme cards. To add a new tab: a `role="tab"` button in `.set-nav` (`data-tab`, `aria-controls`), a `data-pane` panel section in `.set-main`, `set.tab.*` ids and `tools/i18n_check.py`.

## Languages (i18n, 2026-10)

- **Files:** `static/lang/<lang>.json` (`en.json` is the default/fallback, `tr.json`). A flat `{id: text}`; `"_name"` is the language's own name (shown in the language picker). Ids are dotted and meaningful (`menu`/`file.open_default`, `err.exists`, `upd.err.offline`, `wmo.95`, `icon.atom`). A plural value is a `{ "one": ..., "other": ... }` object (the client picks with `Intl.PluralRules`, `vars.n`); placeholders are `{name}`. A new language = a new file under `static/lang/` (the language picker and detection are built automatically from the languages in the dictionary).
- **Loading:** `i18n.py` reads the files; `Handler.send_index()` embeds all dictionaries in the main page in place of `/*I18N*/` inside `<script type="application/json" id="i18n-data">` (no extra request/delay, `<` is escaped). When running from source the dictionary is re-read on every request; in the packaged app once.
- **Client (`static/index.html`, the "languages (i18n)" block):** `t('id', { variable })` active language → `FALLBACK` (`en`) → the id itself. In static HTML `data-i` (text), `data-i-title`, `data-i-ph`, `data-i-aria`, `data-i-html` (texts whose value may contain HTML, trusted); `applyI18n()` translates them all. The English text in the HTML is only the fallback before JS runs (keep it equal to `en.json`). Language: `localStorage` `lang` = `auto` (default: `navigator.language` if it is a dictionary language, otherwise `en`) | a language code; `#s-lang` in Settings. `setLang()` refreshes the static text and the dynamic content (`render()`, weather, the update message `showUpd()`). Date/number format follows `locale()`/`lang`. In JS don't name a local variable `t`: it shadows the translation function (use `tb` for tabs).
- **Server errors:** they carry an id instead of text: `raise AppError("err.exists")`, `AppError("err.folder_missing", path=str(p))`, and for updates `UpdateError("upd.err.offline")` (both are `i18n.AppError`; `UpdateError` is in `updater.py`). The response is `{"error": English default, "code": id, "vars": {...}}`; the client shows it in the active language with `errText(j)` (`error` if the id is not in the dictionary). The update status carries `error_code`/`error_vars`, the root-folder warning `warning_code`/`warning_vars`. The 401/403 pages (`deny("http.no_access")`) are bilingual "English / Türkçe". GET errors also return JSON (`AppError` → 400; only `err.bad_path` is 403).
- **When adding new text:** first the id + English text in `en.json`, then its Turkish counterpart in `tr.json` (placeholders must be the same), and in the code use only the id. **Run `python tools/i18n_check.py`**: it reports ids used in the code but missing from the dictionary, missing in a language, with mismatched placeholders, and unused ones (exit code 1 on errors).
- The setup wizard (`libzie.iss`) is English + Turkish, uses the built-in `{cm:...}` texts, and shows a privacy page (`installer/privacy-en.txt` / `privacy-tr.txt`).

## Desktop app (packaging)

- `app.py` opens the `server.start()` server in a window with pywebview (Edge WebView2 on Windows); `python server.py` is still enough for development. `server.start()` first looks for a running libzie with `/api/ping` on the 11 ports starting at 8765 (if there is one it connects to it and does not start a server), otherwise binds the first free port; if `PORT` is given only that port is tried.
- In the packaged app (`sys.frozen`) `STATIC` is under `sys._MEIPASS`; courses default to `Documents\libzie\materials` and settings are in `%APPDATA%\libzie\settings.json` (when running from source, the project folder as before). `documents_dir()` also finds a Documents folder redirected to OneDrive.
- The build is in GitHub Actions (`.github/workflows/windows.yml`, `windows-latest`, CPython 3.12): `pyinstaller --windowed --onedir --add-data "static;static" app.py` → `libzie-windows.zip` (artifact; also attached to the Release on a `v*` tag). The development machine has no python.org CPython (MSYS2 Python), so it was not built locally.
